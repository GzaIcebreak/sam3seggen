# GeoSAM2 消融 + 三个路线问题的评估

日期：2026-09-06。脚本：`finetune/geosam2_ablate.py`（统一提升/后处理，切换 2D 掩码来源）、`finetune/sam3_track.py`（SAM3 tracker 多视角传播）、`finetune/ablation_score.py`（打分/表格/拼图）。
数据：20 个 PartVerse hard 物体（有 GT，`datasets/geosam2/eval/`）和 10 个外部资产 `datasets/3D拆件.zip`（无 GT，`datasets/ext_bench/`）。

要回答的三个问题：
1. SegviGen 路线里的 DINOv3 特征能不能微调来强化性能？
2. GeoSAM2 的 SAM2 能不能换成 SAM3？能不能逆向它的训练/微调？
3. 不训练 GeoSAM2，用消融看清楚它每一部分值多少；并且一定要测"把 SAM2 换成 SAM3"。

---

## 0. 结论先行

| 问题 | 结论 |
|---|---|
| SAM2 → SAM3 | **不能直接替换权重，但在"传播"这一环节上 SAM3 tracker（无几何、零训练）已经不输 GeoSAM2 自己的 SAM2+LoRA+几何传播**。hard 集 mIoU：SAM3 tracker 2 提示视角 0.276 > GeoSAM2 传播最好的 2 视角 0.254；对 GeoSAM2 传播 p1 的逐物体胜负 13/7。 |
| GeoSAM2 的几何分支值多少 | 在 PartVerse 语义部件上，几何分支相对纯 RGB 传播**没有可测的增益**（geo_p2 0.254 vs sam3track_p2 0.276；geo_p1 0.246 vs sam3track_p1 0.248）。它的收益体现在别处：把 12 视角掩码合成 3D 标签的**提升 + 填充后处理**，这部分我们已经独立复用了。 |
| SAM3 逐视角直接投票（完全不要 SAM2） | 1 视角 0.209 → 2 视角 0.243 → 4 视角 0.244 → 12 视角 0.230。12 视角反而变差：SAM3 各视角之间边界不一致，直接投票带来碎片（段数 8.1、过分割件 5.5 为所有行最高）。**传播（任何一种）都比多跑 SAM3 强**，因为传播保证了跨视角的同一部件同一 ID。 |
| 与 SegviGen 对照 | hard 集上 v6+SAM3 仍是最好：mIoU 0.296、边界 F1 0.704、命名正确率 0.620，所有提升类方法边界 F1 都在 0.50–0.56。最好的提升行（SAM3 tracker p2）对 v6 逐物体 9 胜 11 负。外部资产上各提升行彼此几乎无差别，与 v6 的类无关一致性 0.76–0.83（§3）。 |
| DINOv3 微调 | **不建议现在做**。瓶颈已被定位在采样轨迹上的颜色决策（v6 证明），不在特征感知；DINO 特征又是几何和纹理两级的唯一条件，动它先伤"整块"。若要做，只有一种低风险方式（§5）。 |
| 逆向 GeoSAM2 训练 | **可行、代价可控，但优先级不高**。它的训练配方已经完整（§6.2），数据我们有比它多 3 倍且是语义部件的 PartVerse；但消融显示传播模块不是短板，重训它改善的正是那块不重要的部分。 |

一个附带发现：**GeoSAM2 的 `prepare_mesh_and_point_cloud` 有变换顺序 bug**（先平移后缩放，渲染器是先缩放后平移）。对 bbox 中心不在原点的资产（dog：偏移 −0.42、缩放 0.94）网格和深度图错开约 5–10 % 尺寸，1e-3 深度测试只剩 9 % 的面通过，其余 91 % 靠最近面填充。修正后（`geosam2_ablate.prepare_mesh`，并已同步修 `GeoSAM2/inference.py`）dog 通过率 0.09 → 0.92。他们的示例网格是预先居中的，所以看不出来。**受影响的旧结果**：`ext_bench` 里 dog / mickey / pineapple / shelf 四个资产的 GeoSAM2 single/dual 行；PartVerse hard 集（偏移为 0）不受影响。

## 1. 消融设计

所有行共享同一条后半段（GeoSAM2 的代码）：
12 视角 1024² 渲染（normal / depth / RGB / alpha）→ 2D 标签图 → `lift_2dmask_3d`（每个面采 5 点做 1e-3 深度可见性测试，逐点跨视角取众数）→ 面级投票 → `complete_labels`（去小连通块、最近面填充）。**唯一变量是 2D 标签图从哪来。**

| 行 | 2D 标签图来源 | 用到的模型 |
|---|---|---|
| `sam3_pK`（K = 1, 2, 4, 12） | 直接在 K 个均匀分布的视角上跑 SAM3（概念向量库 + 用户提示），不传播 | SAM3 |
| `geo_pK`（K = 1, 2, 4） | K 个视角的 SAM3 掩码作提示，GeoSAM2 沿 12 视角传播；K 次传播结果逐像素多数票，平局按与提示视角的角距 | SAM3 + GeoSAM2（SAM2 B+ ×2 + LoRA + 几何融合） |
| `lift:sam3track_pK`（K = 1, 2, 4） | 同样的 K 个提示，用 **SAM3 tracker**（`facebook/sam3` 的 `Sam3TrackerVideoModel`，PE 骨干，RGB 输入，无几何，未做任何训练）沿 12 视角传播 | SAM3 + SAM3 tracker |

- `sam3_p12` = "SAM3 完全取代 SAM2"；`lift:sam3track_pK` = "SAM2 传播换成 SAM3 传播"（问题 2/3 要求的测试）；`geo_pK` 是 GeoSAM2 自己的传播。
- 提示视角：`match` 锚视角（与 SegviGen 用的正面图最接近的那个）+ 均匀分布的其余 K−1 个。所有行的部件集合相同（用户给的名字），没有 GeoSAM2 原版 single 里"对面自动分割出匿名新部件"那一步，所以 §2 表里 GeoSAM2 原版行段数更多、mIoU 略高不是同口径，只作参考。
- `sam3track` 传播实现：以锚视角为中心分正、反两个半圈各跑一次 tracker（视角环是闭合的，视频模型是线性的），重叠帧对 logits 取平均；提示视角保留 SAM3 原掩码。
- 两个修掉的实现问题：(a) K<12 的行里未提示视角原本会投 999（"无主"）票压过有标签的像素，现在这些视角按 alpha 全 0 处理，不参与投票；(b) 变换顺序 bug（见 §0）。另外 GeoSAM2 的 `complete_labels` 里"连通块重编号"用 0 维张量做字典键，实际永远不触发，所以 `faces_inst.npy` 与 `faces.npy` 相同，只对后者打分。

打分：`eval_parts.py`（Hungarian 匹配 mIoU、名字匹配的语义 mIoU、命名正确率、边界 F1、过/欠分割计数、小件召回、留白比例）。

读法：
1. **传播的价值 ≈ 0.04 mIoU，且不来自几何。** 单提示视角下三种"补全其余 11 个视角"的方式：不传播（sam3_p1）0.209，GeoSAM2 几何传播 0.246，SAM3 tracker 0.248。多提示视角下 SAM3 tracker 领先更多。GeoSAM2 论文的对比对象是 SAM2 原版传播，它的几何分支相对 SAM2 有增益是可信的；但 SAM3 tracker 的 PE 骨干本身已经比 SAM2 Hiera 强出这一段。
2. **多跑 SAM3 不如传播。** 4 → 12 视角 mIoU 下降、段数上升，是 SAM3 逐视角独立分割的边界不一致直接进了 3D 投票。这也说明"多视角语义图"这一需求最好由"锚视角 SAM3 + 传播"给，而不是每个视角各跑一次 SAM3。
3. **提示视角 2 个是甜点，4 个开始回落。** 4 个视角互相冲突时的多数票会把提示视角自己的高质量掩码也覆盖掉；p4 的边界 F1 在 GeoSAM2 和 tracker 两条线上都低于 p2。
4. **SegviGen 在边界和命名上仍显著领先**（边界 F1 0.70 vs ≤0.56，命名 0.62 vs ≤0.43），提升类方法在小件召回上略好（0.07 vs 0.04）但整体 mIoU 没赶上 v6。这和用户"整块优先"的目标一致：提升类方法天然把 2D 边界噪声带到 3D。
5. hard 集 mIoU 整体偏低（0.2–0.3）是集合本身的性质（细小部件、GT 粒度比用户提示细），横向比较仍有效。

## 4. 两条路线现在怎么定位

| | SegviGen（v6 + SAM3 正面图） | 提升类（SAM3 锚视角 + 传播 + GeoSAM2 提升/填充） |
|---|---|---|
| 边界 / 整块 | 生成式，切口跟随 3D 结构，边界 F1 0.70 | 2D 边界投影到面，F1 0.50–0.56，细杆/薄片处碎 |
| 语义 / 命名 | 依赖正面 SAM3 图 + 模型对 3D 的理解，命名 0.62 | 直接沿用 SAM3 的名字，命名 ≤0.43（传播错、投票错都记在名字上） |
| 看不到的面 | 模型自行补全，整体一致 | 最近面填充，大面积背面容易被邻近部件吞掉 |
| 小件 | 会漏（小件召回 0.037） | 略好（0.05–0.07），但也更碎 |
| 可控性 | 只有正面一张图；改提示需重跑生成 | 每个视角都可加/删提示，掩码可编辑后重提升 |
| 时间 | 25 步采样 + 解码，约 1–2 分钟 | 8–20 s（SAM3 tracker 路线最快） |
| 训练依赖 | 需要我们微调过的 LoRA | 零训练（SAM3 + SAM3 tracker + 几何后处理） |

工程化建议保持双管线，但提升类那一路**用 SAM3 tracker 做传播、GeoSAM2 只保留提升与填充代码**——它的 SAM2 权重、几何分支和 LoRA 在我们的数据上都没有体现价值，还多一份 155 M 权重和第二个环境。

## 5. 问题 1：微调 SegviGen 里的 DINOv3

现状（`trellis2/modules/image_feature_extractor.py`）：DINOv3 ViT 在 512² 上跑一次，`eval()` + `@torch.no_grad()`，输出约 1024 个 patch token，作为**稀疏结构生成和 SLAT 生成两级 flow transformer 的唯一交叉注意力条件**；finetune 数据管线把它离线算好存成 `cond.pt`，训练时不再过 DINO。

能不能做：技术上可以（LoRA 到 DINO 的 Q/K/V，训练时在线提特征），代价是每步多一次 ViT-L 前反向、数据集里的 `cond.pt` 缓存全部失效，单卡上训练时间约 2 倍以上。

值不值得做，看瓶颈在哪：

| 证据 | 含义 |
|---|---|
| 从 latent 线性探针读颜色，留出物体调色板准确率 96.5 %（含 GREY 类 90.9 %） | 2D 图里的颜色信息**已经**被 DINO 特征完整带进了 latent，感知不是短板 |
| v4（显式颜色 CE，单步 x0）颜色 CE 4.25 → 0.84，但 fidelity 不变 | 训练时能"看见"正确颜色，采样轨迹上却不按它走 |
| v6（把监督放到采样器真正经过的 x_t 上）fidelity 0.617 → 0.663，hard 集 mIoU 0.278 → 0.296 | 真正动了结果的是**决策**侧的监督，不是特征侧 |
| v5（把部件名字直接加到 DINO patch token 上）fidelity 反而掉到 0.19 | 改动 DINO token 的分布本身就有代价：冻结的 K/V 投影把这些当分布外向量 |

所以微调 DINO 是在**不是短板的一环**上花 2 倍训练成本，而且风险在最在意的地方：同一份特征也决定几何（稀疏结构级），特征分布一动，"整块"这一 SegviGen 最大优势最先受影响。

如果一定要试，只推荐一种低风险形式：**LoRA r=8 只加在 DINO 最后 4 个 block 的 Q/V 上，和 v6 的轨迹损失一起训，SLAT 级用、稀疏结构级仍用冻结特征**（两级分别缓存两份 cond），门槛沿用 §2 的 `eval_parts`：hard 20 个 mIoU +0.02 以上且边界 F1 不降才算通过。预期收益：低。排在 GeoSAM2 路线的所有事项之后。

真正能让 DINO 特征"更语义"的是 PatchAlign3D 式的**局部特征-文本对比对齐**，但那是把 2D 图换成语义 token 的另一套条件，等价于重新设计 SegviGen 的输入，不是微调。

## 6. 问题 2：GeoSAM2 的 SAM2 换成 SAM3；逆向训练

### 6.1 直接替换权重：不行

GeoSAM2 checkpoint（`ckpt/geosam2.pt`，1119 个张量，约 155 M 参数）的构成：

| 模块 | 参数 | 说明 |
|---|---|---|
| `image_encoder.trunk`（normal 图） | 68.8 M | SAM2.1 **Hiera B+**，每个 block 的注意力投影上 LoRA r=4（`linear_a_*/linear_b_*`） |
| `pos_map_encoder.trunk`（position 图） | 68.8 M | 同上，第二份 Hiera B+ + 独立 LoRA |
| `feature_fusion.fusion_{low,mid,high}` | 3 × 1.2 M | 零初始化的 3×3 卷积，逐 FPN 层把 point-map 特征残差加到 normal 特征上 |
| `memory_attention` / `memory_encoder` / `sam_mask_decoder` / prompt encoder | ≈ 12 M | SAM2 原件，冻结（论文只额外训了 IoU 预测头） |

LoRA 和融合卷积的形状、层位都绑定在 Hiera B+ 的四个 stage 上；SAM3 tracker 用的是 Perception Encoder ViT（单尺度 patch token、不同通道数）加它自己的 memory encoder / decoder。没有一个张量能对上，"换骨干"等于重训 LoRA + 融合 + 适配 memory 接口。

### 6.2 逆向训练：可行，配方已经清楚

论文和代码给出的训练细节：SAM2.1 B+ 初始化；LoRA r=4 加在 normal / position 两路图像编码器所有 Q、K、V 投影上；残差融合卷积（零初始化）和 IoU 预测头可训，其余冻结；SAM2 标准损失（focal + dice + IoU 预测 + 出现性）；约 4700 个自标注物体，**按网格连通性分解得到部件**（不是语义部件）；每物体 12 视角 1024² normal / position / depth，按逆时针排成"视频"，memory bank 用首帧复制引导；50 epoch、8 × A800、batch 8、lr 5e-5。

我们手里有：Meta `sam2` 仓库的 `training/`（视频式数据加载 + 上述损失），`geosam2_render.py`（同样的 12 视角 normal/depth/position 输出），PartVerse 14 303 个物体的**语义**部件面标签（外加我们复核的 2000 条）——比它的数据多 3 倍且粒度是我们要的。要补的是：把 LoRA/融合模块接到 sam2 训练图上（约 300 行），以及把面标签渲染成 12 视角掩码序列（渲染器已有 face id 通道可复用）。单卡估算：从 GeoSAM2 权重继续训 PartVerse 3–5 个 epoch 约 1–2 天；从 SAM2 从头照原配方跑 50 epoch 约两周，不建议。

**对 SAM3 tracker 做同样的事**要难得多：`facebookresearch/sam3` 的 `sam3/train` 只提供检测器（图像、文本提示）的微调配置，tracker 的训练配置至今没有公开（issue #470 仍开着）；PE 骨干接几何分支的融合位置也要自己设计。另一方面 2026-03 发布的 SAM 3.1 tracker（Object Multiplex，多目标共享 memory）可以直接替换我们现在用的 `facebook/sam3` tracker，是零成本的升级项。

### 6.3 该不该做：现在不该

消融说明重训能改善的是**传播模块**，而传播模块在我们数据上的三种实现（GeoSAM2 几何传播、SAM3 tracker、甚至 4 视角直接投票）mIoU 都在 0.244–0.276 这 0.03 的窄带里，真正拉开差距的是：
- 锚视角 SAM3 掩码本身的质量（概念向量库让 2D mIoU 0.288 → 0.368，是上游已验证的收益）；
- 提升/填充阶段的几何后处理（1e-3 深度测试在复杂网格上只让 50–70 % 的面通过，其余靠填充；这是几何计算问题，不是学习问题）；
- 3D 边界的整块性（SegviGen 的强项，提升类方法结构上做不到）。

把逆向训练的算力花在这三处之外，回报最低。若日后要做，用 PartVerse 语义部件微调 GeoSAM2 的 LoRA 是路线里最便宜的一项（1–2 天），且能顺带得到"语义部件粒度"的传播器；但它仍然只是把 0.25 拉向 0.28。

## 7. 提升 GeoSAM 路线：SAM2 → SAM3 的收益，以及下一步

### 7.1 SAM2 → SAM3 实测收益（hard 20，同一提升/填充）

| 提示视角 | GeoSAM2 传播（SAM2 B+ ×2 + LoRA + 几何） | SAM3 tracker 传播（RGB，无几何，零训练） | Δ mIoU | 其他 |
|---|---|---|---|---|
| p1 | 0.246 | 0.248 | +0.002 | 过分割件 4.5 → 3.9 |
| p2 | 0.254 | **0.276** | **+0.022** | 小件召回 0.037 → 0.074；13.9–19.4 s → 10.6 s |
| p4 | 0.249 | 0.259 | +0.010 | 边界 F1 持平（≈0.55） |

外部资产上两者与 v6 的一致性、段数、碎片都在噪声内。结论：**收益为正但小（≤ +0.02 mIoU），换来的是零训练、少一份 155 M 权重和一个独立环境**。我们测的是"传播环节换 SAM3"，SAM3 只看 RGB 没有 normal / position 图；要做"带几何分支的完整替换"必须训练（§6.1），而消融显示几何分支本身在我们数据上没有可测增益，所以完整替换的期望回报同样小。它不是主要杠杆——所有传播实现的上限都被下面三件事压着。

### 7.2 下一步（按预期收益 / 成本排序）

| # | 动作 | 针对的问题（数据） | 预期 | 成本 |
|---|---|---|---|---|
| 1 | **精确可见性**：用 face-id 渲染（Blender 管线已有）替代 1e-3 绝对深度阈值 + 每面 5 点采样；或至少改成随深度梯度缩放的相对阈值 | 20 万面资产提升后原始留白 0.3–0.6（robot / car / plane），一半的面靠最近面填充，背面被邻近部件吞 | 直接命中 50–70 % → 90 %+，所有提升行同时受益 | 1 天，纯几何 |
| 2 | **软投票 + 面图正则化**：每个面累计各视角的标签分数（按视线-法线夹角、tracker 置信度、像素数加权）而不是逐点硬多数票；再在面邻接图上做一次 graph cut / MRF，边界代价用二面角和凹性 | 碎片 2.0–2.7 / 段、过分割件 4–5 / 物体、边界 F1 0.55 vs v6 0.70 | 碎片降到接近 1、边界 F1 向 0.65 靠；这是"整块"这一目标的直接杠杆 | 1–2 天 |
| 3 | **第二个提示视角自适应**：第一次传播后选"未标注可见面积最大"的视角跑 SAM3 作第二提示，不用固定对面；4 视角时按置信度而不是多数票化解冲突 | p2 是甜点、p4 回落（多数票覆盖了高质量提示） | 覆盖背面小件，避免 p4 的回落 | 0.5 天 |
| 4 | **段级命名**：提升后按面积和可见置信度对每个连通段重新投票名字，同名相邻段合并 | 命名正确率 0.38–0.43 vs v6 0.62 | 命名 +0.1 量级 | 0.5 天 |
| 5 | **锚视角 2D 掩码**：概念库继续扩（已验证 2D mIoU 0.288 → 0.368）、细杆部件高分辨率 tile、负提示压误检、SAM3-I 复核 | 整条路线的上限就是锚视角 SAM3 的 2D 质量 | 每 +0.05 2D mIoU 约 +0.03 3D | 持续 |
| 6 | **与 SegviGen v6 融合**：v6 的块边界内取提升路线的多数名字 | 两列强项互补（§4） | 边界拿 v6 的 0.70、命名/小件拿提升路线的 | 1 天 |
| 7 | 训练类：PartVerse 语义部件微调 GeoSAM2 LoRA；SAM 3.1 tracker 替换；DINOv3 LoRA | 见 §5、§6 | 小 | 1–2 天起 |

执行顺序建议 1 → 2 → 3 → 4，每步用 §2 的 `eval_parts`（hard 20，mIoU / 边界 F1 / 碎片）做门槛；5 与 6 并行推进；7 放最后。
