## 0.1 技术路线 A–E

方案原文在 `PLAN_concept_bank_v4.md`。A–E 是「只改文本侧 / 损失 / 评测尺子、SAM3 冻结」这一档里的五条；D 排在批次 5，本轮没做。下面按路线拆开写：各攻哪条缺口、怎么做、实测落到哪。

### A. 跨名字竞争（最高优先）

**缺口。** v3 对每个提示词独立算 BCE+Dice，再加 presence BCE。名字之间没有竞争项。部署时 `colorize` 却是逐像素归属：多个名字的掩码按面积从小到大叠涂，谁盖住这个像素谁说话。训练优化的是绝对分数，下游要的是相对排序（这个像素属于 `arm` 还是 `body`）。这正好解释 v3 的 mIoU 涨了 0.08、难负例误检一动不动。

**做法。** 同一张图的全部正名 + 采样负名放进一个 batch，每个像素对「名字维」做 softmax（外加背景 logit），用 `ids.npy` 当标签算交叉熵；BCE+Dice 降权作辅助；再加 margin：负名在任意前景像素上要比赢家低一截。方案估计难负例 0.188 → 0.13～0.15，mIoU +0.02～0.04。风险是大部件（`body`）主导 CE，要按面积做类平衡。

**实测。** 两条跑次都从零训 3 epoch。`v4_AE`：`--pixel_ce 1 --bce_weight 0.4 --margin 0.2 --name_bias`，`max_prompts 12`——46% 物体超过 6 个部件，12 个名额扣掉 6 个负例后正名被丢掉，softmax 经常看不见 `arm` vs `body`。`v4_A3E`：正名优先进 batch、`--max_prompts 20 --ce_mode painted --ce_balance sqrt`，公平对照。阈值 0.5 上 AE ep3 全面不如 v3（难负例略好：0.174 vs 0.189）；A3E ep2 检出回到 v3（涂对 0.541），难负例和涂错更差（0.225 / 0.216）。MakerWorld 上 A3E 涂对 0.635 虚高，留出集没把「分得清」学稳。

**判定。** 未通过。跨名字 CE 在当前 bank 容量（一次平移）下压不住误检，或把绝对分数校准打坏了。正名必须同场也救不了。不要再从零扫 CE 权重。

### B. 可学习上下文 token（高优先）

**缺口。** `E_0 + E[name]` 以同一方向广播到 `pooler_output` 的每一个文本 token，`last_hidden_state` 不动。整个 bank 的表达力 = 文本特征空间里做一次平移。`E_0` 想表达「灰模、无纹理、部件级而非整体」，但改不了 token 之间的结构，也改不了解码器怎么注意图像。

**做法。** CoOp 式：在 `pooler_output` 前面拼 K 个全名字共享的可学习 token（K = 4，每个 256 维，约 2K 参数），`E[name]` 照旧。从 v3 热启动 3 epoch，`--ctx 4`。方案估计 mIoU +0.02～0.04、灰 −0.03～0.05；风险是过拟合 PartVerse 灰模风格。

**实测。** 阈值 0.5：mIoU 0.372 → 0.404，灰 0.378 → 0.325，涂对 0.541 → 0.577，第 2、3 个 epoch 还在动（不像 v3 第 1 个 epoch 就饱和）。难负例同步 0.189 → 0.246，涂错跟着涨。MakerWorld 涂对贴着 v3（0.579 vs 0.581），mIoU 虚高来自多检出。训练损失从热启动起就在 0.80–0.95，是 v3 目标的地板：BCE+Dice 不罚认错，SAM3 冻结，ctx 只有 2K 参数。

**判定。** 未通过。ctx 能继续推检出，难负例同步变差，还是「更敢涂」不是「分得清」。若只想多涂、能接受更高误检，ep1 是 B 里难负例最轻的一档（0.232）。

### C. 组合式偏移 + 近邻回退（高性价比）

**缺口。** `--min_count 8` 只留 280 个名字，覆盖约 82% 部件实例；其余只吃 `E_0`。部署场景恰恰是最坏情况——外部资产的 `fender` / `pommel` / `pauldron` 大概率不在这 280 个里。

**做法。** 两件便宜的事。(1) 推理侧近邻回退：词表外名字用文本余弦 > τ 的已知名 `E` 做加权平均，零训练。(2) 按词学 `E_word`，名字偏移 = 词偏移之和，整名 `E[name]` 当残差；顺带把 `min_count` 降到 4。方案估计留出集涨不多，外部资产提示词命中率应明显改善。

**实测。** 近邻回退单独加在 v3 上：cos > 0.8 留出 / MW 持平（0.371 / 0.400）；cos > 0.7 两边都退（0.363 / 0.384）。MakerWorld 45 个词表外名字和 280 词表够不上 0.8，降阈值会借错邻居。词偏移 `v4_C`（v3 热启动，词表 477 名 / 477 词）：难负例能压到 0.132（ep2），检出和上色都退（灰 0.515、涂对 0.422）；ep3 难负例 0.153、涂对 0.483，仍不如 v3。MakerWorld ep3 涂对 0.539，没超过 v3 的 0.581。低频名进词表后模型更不敢涂。

**判定。** 未通过。扩词表 / 词偏移会压难负例，但以灰像素换来，外部集也没兑现。等更大、名字更干净的数据再试扩词表。

### D. 在线难负例挖掘（中优先，本轮未做）

**缺口。** `--neg_mode mixed` 在训练前静态采样负例（文本余弦挑共现 / 相似名，跳过 cos > 0.85 的近义）。模型第 1 个 epoch 就学会应付这批固定负例，第 2、3 个 epoch 空转——v3 的收益几乎全在第 1 个 epoch，不是数据用完了，是这个损失已经被满足了。

**做法。** 每个 epoch 结束后用当前 bank 在训练集上跑一遍，记下实际误检的 (物体, 名字) 对，作为下一 epoch 的负例并给更高权重。方案估计主要作用是让后两个 epoch 不再空转，配合 A 把难负例往 0.12 压。成本：每 epoch 多一次训练集前向（约 +20 min）。

**实测。** 批次 5，本轮没跑。A 已经说明跨名字 CE 在当前容量下学不动相对排序；D 换的是负例来源，不换「看不见认错」的目标。没做的原因：A/B/C/E 都没过关，先换目标比先换负例队列更对症。更大的数据来了之后，对照仍是 v3 + F，不要先叠 D。

### E. 每名字阈值偏置（近乎免费）

**缺口。** 全局一个 `--threshold`。`body` 这类会过度扩张的名字和细杆类名字需要的松紧度完全不同；v3 表里也能看出阈值一动、各项指标就整体平移。

**做法。** 给每个名字学一个标量偏置 `b[name]`（280 个参数），叠在 mask logit 上。方案估计等效于「免费拿到半档阈值」，灰和误检之间的权衡点更好。成本几乎为零，和 A 绑在同一批训练。

**实测。** 没有单独消融，始终和 A 一起开 `--name_bias`（`v4_AE` / `v4_A3E`）。两条跑次都没过关：要么全面不如 v3，要么检出回到 v3 而难负例 / 涂错更差。偏置没有把工作点从「整体放宽 / 整体收紧」里拆开——默认阈值 0.3 上 AE 的 mIoU 能到 0.405、涂错 0.269，还是同一条曲线。

**判定。** 未通过（随 A）。280 个标量改不了「名字之间无竞争」这件事；和跨名字 CE 绑在一起时，也救不了 CE 把绝对分数校准打坏。

## 2. 批次 1（F）：通过

F 不改模型，只在 `evaluate` 里按 `colorize` 叠涂出逐像素归属。验收：复现 v3 表 + 新增上色列。两件都做到了。

阈值 0.5，留出集：

| | mIoU | 灰像素 | 难负例 FP | 涂对 | 涂错 | 未涂 | 涂错占比 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 裸 SAM3 | 0.287 | 0.659 | 0.186 | 0.318 | 0.096 | 0.587 | 23.2% |
| **v3** | **0.372** | **0.378** | 0.189 | **0.541** | 0.205 | 0.254 | 27.5% |

结论：

1. v3 的收益是真的，性质是「涂得多了」不是「涂得准了」。灰像素 0.587 → 0.254，涂对翻 1.7 倍，涂错也翻倍。
2. v3 基本沿着裸模型的多检出曲线走。裸模型阈值 0.3（涂对 0.404 / 涂错 0.151）和 v3 阈值 0.6（0.436 / 0.169）几乎在同一条权衡线上。难负例 FP 持平，说明学到的主要是「灰模、要敢检出」（`E_0` 0.13→4.2），不是「arm 和 body 怎么分」。
3. 涂错 0.096 → 0.205 里，约 0.07 是体量效应（涂色像素 41%→75%，精度不变也会涨到 ~0.17），约 0.035 是精度从 23.2% 掉到 27.5%。后者来自：大部件掩码外溢、名字之间无竞争、以及一部分标注口径（`head→helmet`、`rear wheel→wheel`、`body→torso`）。

难负例误触（v3，t=0.5，136 次）最多的负例：`body` 28、`head` 15、`base` 14、`leg` 11。被抢最多的 GT：`body` 12、`torso` 11、`wheel` / `helmet` 各 6。

MakerWorld 上同样成立：裸 0.207 / 涂对 0.230 → v3 0.400 / 0.581。

**F 通过。之后一律用上色图选模型。**

## 9. 筛选结论

1. **F 留下。** 评测必须带上色图；只报 mIoU 不作数。
2. **默认产物仍是 v3 `bank.pt`。** A、B、C、E、G、H 都没过关。D 本轮没做（见 §0.1）。
3. **A：** 名字竞争在「一次平移」的容量里学不动相对排序；正名必须同场也救不了。
4. **B：** ctx 能继续推检出，难负例同步变差。还是「更敢涂」，不是「分得清」。
5. **C：** 扩词表 / 词偏移会压难负例，但以灰像素换来，外部集也没兑现。
6. **E：** 每名字标量偏置没把工作点从「整体放宽 / 收紧」里拆开；始终和 A 绑在一起训，单独也救不了。
7. **G：** 现有数据做不了多视角。三模板表决打散了 v3 的单模板校准，留出和 MakerWorld 都退。
8. **H：** LoRA 第一次把损失压到 v3 地板以下，改的是分数校准。0.5 上难负例好看、检出塌掉；0.4 上像把工作点挪回去，仍不如同阈值的 v3，外部集更差。
9. 估计区间没有同时达到。B 碰到 mIoU / 灰，难负例走反；H 碰到难负例，mIoU / 灰走反。

这 2000 个物体上，A–H 里能做的都试过了。下一步要么换一条能看见「认错」的目标，要么等更大、名字更干净的数据。不要叠加这些失败配置。更大的数据集来了之后，对照用 **v3 + F**。
