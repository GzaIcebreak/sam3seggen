# 概念库 v4：继续提升的方案

配套：数据格式与 v3 结果见 `DATA_concept_bank.md`；训练脚本 `finetune/concept_bank.py`，注入点 `finetune/sam3_bank.py`。
数据 [`Zaun1996/segvigen-pv-2view`](https://huggingface.co/datasets/Zaun1996/segvigen-pv-2view)，v3 权重 [`Zaun1996/sam3-concept-bank`](https://huggingface.co/Zaun1996/sam3-concept-bank)。

---

## 0. v3 停在哪里，为什么

留出集 200 物体 / 1068 提示词，阈值 0.5：mIoU 0.288 → **0.368**，灰像素 0.654 → **0.381**，难负例误检 0.186 → 0.188（持平）。

三个事实决定了下一步该做什么：

1. **收益几乎全在第 1 个 epoch**（0.351 → 0.365 → 0.368）。不是数据用完了，是**这个损失已经被满足了**——继续训练学不到新东西。
2. **剩下的主要错误是「认错」，不是「找不到」**。阈值 0.5 上难负例误检 0.188，即约五分之一的干扰名字（共现的、文本相似的）仍会吐出像素。
3. **容量确实很小**。`sam3_bank.run_prompts` 把 `E_0 + E[name]` 以 `.view(n, 1, -1)` 广播到 `pooler_output` 的**每一个文本 token** 上，`last_hidden_state` 完全没动。所以整个 bank 的表达力 = 在文本特征空间里做一次平移，方向对每个 token 都一样。

对应地，下面 A 攻第 2 条，B 攻第 3 条，D 攻第 1 条。**A 和 F 建议先做**，因为它们同时改变「优化什么」和「按什么选模型」；其余是加法。

---

## A. 让训练目标和部署目标一致：跨名字竞争 ★最高优先

**缺口。** `concept_bank.py` 现在对每个提示词**独立**算 `bce_dice`，再加一个 presence BCE。名字之间没有任何竞争项。但部署时 `sam3_to_2dmap.colorize` 做的是**逐像素归属**：多个名字的掩码按面积从小到大叠涂，谁盖住这个像素谁说话。也就是说下游真正需要的是**相对排序**（这个像素属于 `arm` 还是 `body`），而 BCE 优化的是绝对分数。两者不是一回事，这正好解释了为什么 mIoU 涨了 0.08 而难负例误检一动不动。

**做什么。** 一次前向把**同一张图的全部名字 + 采样的负例名字**放进一个 batch（现在 `--max_prompts 12` 已经是分块批处理，改动不大），然后在**每个像素**上对「名字维」做 softmax（外加一个背景 logit），用 GT 的 `ids.npy` 当标签算交叉熵。保留原来的 `bce_dice` 作为辅助项，权重降到 0.3～0.5。

```
loss = w_ce * pixel_CE(softmax_over_names(logits), ids)      # 新增，主项
     + 0.4 * bce_dice(...)                                    # 保留，维持绝对分数校准
     + 0.5 * presence_bce(...)
```

再加一个 margin 项直接打误检：对负例名字 `j` 和任意前景像素 `p`，要求 `max_i logit_i(p) > logit_j(p) + m`（m 取 1.0 左右），只对违反的项计损失。

**预期。** 难负例误检是这条最可能真正下来的指标，0.188 → 0.13～0.15；mIoU 顺带 +0.02～0.04。**风险**：像素 CE 会被大部件主导（`body` 占一半像素），要按部件面积做类别平衡——上游 `cells.palette_ce` 已经有现成的类平衡写法可以照搬。

**成本。** 改 `concept_bank.py` 的训练循环，约半天；训练时长不变（还是 3 epoch / 70 min），显存略升（负例也要出掩码，可用 `--max_prompts` 压）。

## B. 提示词侧扩容：可学习上下文 token ★高优先

**缺口。** 见第 0 节第 3 条：一个方向平移到底。`E_0` 想表达的是「灰模、无纹理、部件级而非整体」这个域偏移，但它只能整体推一下，不能改变文本 token 之间的结构，也不能改变解码器怎么注意图像。

**做什么。** CoOp 式提示词微调：在 `pooler_output` 序列**前面拼 K 个可学习 token**（K = 4～8，每个 256 维，同时把 `attention_mask` 补 1）。这些 token 全名字共享，是 `E_0` 的严格更强版本。`E[name]` 保持不变继续用。

改动集中在 `sam3_bank.run_prompts`：

```python
ctx = ctx.expand(n, K, D)                       # 可学习，[K, D]
pooled = torch.cat([ctx, pooled + offsets], 1)  # [n, K+L, D]
attention_mask = F.pad(attention_mask, (K, 0), value=1)
```

参数量 8 × 256 = 2 K，仍然可以忽略。可选加强：再学一个 rank-16 的低秩调制 `pooled + W_up(W_down(pooled))`（8 K 参数），让 bank 能**压制**文本特征里「整个物体」的成分——这是 `body` 抢走全身的直接原因。

**预期。** mIoU +0.02～0.04，灰像素 −0.03～0.05。**风险低**（还是只训极少参数，SAM3 全冻结）。真正的风险是 K 太大时过拟合 PartVerse 的灰模风格，外部资产反而变差——所以必须用第 F 节的外部资产抽查把关。

---

## C. 长尾与没见过的名字：组合式 + 近邻回退 ★高性价比

**缺口。** `--min_count 8` 只留下 280 个名字，覆盖约 82 % 的部件实例；剩下 18 % 只吃 `E_0`。而**部署场景恰恰是最坏情况**——外部资产的名字（`fender`、`muzzle brake`、`pauldron`）大概率不在这 280 个里。

**做什么。** 两件事，都很便宜：

1. **组合式偏移**：按词学 `E_word`，名字的偏移 = 其词的偏移之和（或一个小注意力加权）。`arm joint` = `E[arm] + E[joint]`。词表比名字表小得多、每个词出现次数多得多，长尾名字于是能拿到有意义的偏移而不是零。可以和现有的整名 `E[name]` 相加共存（整名当残差）。
2. **推理侧近邻回退**：遇到词表外的名字，用文本余弦 > τ（比如 0.8）的已知名字的 `E` 做加权平均。**零训练成本，改十行推理代码**，现在就能给外部资产用上。脚本里已有 `--syn_cos 0.85` 在做同类的近义判断，逻辑可以复用。

顺带把 `--min_count` 从 8 降到 3～4，靠 `--l2` 和「向组合式先验收缩」控制过拟合。

**预期。** 留出集上涨得不多（那里的名字大多是高频的），但**外部资产的提示词命中率**应该明显改善——这才是工程上真正吃亏的地方。v3 现在是 51 个提示词命中 48 个。

## D. 难负例挖掘 ★中优先

**缺口。** `--neg_mode mixed` 是在训练前**静态**采样负例（`draw_hard` 用文本余弦挑共现/相似名字，跳过 cos > 0.85 的近义词）。模型第 1 个 epoch 就学会了应付这批固定负例，于是饱和。

**做什么。** 每个 epoch 结束后，拿当前 bank 在训练集上跑一遍，记下**实际误检**的 (物体, 名字) 对，把它们作为下一个 epoch 的负例并给更高权重。相当于把静态负例换成在线难例。

**预期。** 主要作用是让第 2、3 个 epoch 不再空转，配合 A 一起把难负例误检往 0.12 压。**成本**：每 epoch 多一次训练集前向（约 +20 min）。

---

## E. 每名字阈值偏置 ★近乎免费

**缺口。** 全局一个 `--threshold`。但 `body` 这类会过度扩张的名字和细杆类名字需要的松紧度完全不同，v3 表里也能看出阈值一动、各项指标就整体平移。

**做什么。** 给每个名字学一个标量偏置 `b[name]`（280 个参数），叠在 mask logit 上；或者再加一个温度 `τ[name]`。用第 F 节的上色图指标来选。

**预期。** 灰像素和误检之间的权衡点更好，估计等效于「免费拿到半档阈值」。成本几乎为零，建议和 A 一起做。

---

## F. 用「上色后的图」选模型 ★做其他项之前先做

**缺口。** 现在按 `miou`（名字级像素并集的 IoU）选 epoch 和阈值。但下游拿到的不是每个名字的并集，而是 `colorize` 叠涂后的**一张图**。两者可以背离：某个名字 IoU 涨了，但因为面积排序变了，叠涂后反而盖住了别人。

**做什么。** 在 `evaluate` 里加一条：直接调用 `sam3_to_2dmap.colorize` 出图，和 `ids.npy` 比**逐像素归属准确率**、以及「被涂色部件数 / 可见部件数」。这两个数才是 SegviGen 和 GeoSAM2 真正消费的东西。然后按它们选 epoch 和阈值。

同时把**外部资产抽查**固定成流程的一环（`ext_bench.py` 那 10 个资产），防止 B / C 过拟合到 PartVerse 的灰模风格。

**成本。** 半天，纯评测代码。**这一项自己不带来提升，但没有它，A/B/C/E 的提升都不可信。**

---

## G. 更多视角 + 模板集成 ★需要重新渲染

**缺口。** 训练只用了 `az0` 和 `az135` 两个方位，而部署路径（`ext_bench.py` / `geosam2_masks.py`）最多用 12 个视角。斜后方视角上部件被压缩、被遮挡，bank 从没见过。另外 `--template` 只有一个 `"{name}"`，没有模板集成。

**做什么。** 渲染扩到 6 个方位 + 2 个俯仰（数据量 ×4，标注成本为零，但**需要 `parts/*.glb`**，那在 133 GB 的完整集里，不在已上传的最小包里——要么在云上重新渲染，要么单独传 `parts/`）。模板方面训练时随机在 3～4 个模板间采样、推理时平均，这一项不需要新数据。

**预期。** 视角扩充对遮挡视角的稳健性帮助明显，但要先解决数据传输；模板集成通常值 +0.01～0.02，属于顺手做。

---

## H. 最后手段：给 mask decoder 加 LoRA

**缺口。** A～G 都还在「只改文本输入」的框架里。上限就是文本嵌入空间里能表达的东西——改不了 SAM3 的解码器**怎么根据文本去看图像**。

**做什么。** 在 SAM3 mask decoder 的 cross-attention 上挂 LoRA（rank 4～8，几 M 参数），图像编码器保持冻结。这是这条路线上最大的杠杆。

**为什么放最后。** 一是过拟合风险质变——PartVerse 的灰模风格和部件划分口径会被学进解码器，外部资产上可能反而退化，而外部资产才是目标场景；二是产物从 287 KB 变成几 M，部署与版本管理都变重；三是 A～E 加起来的成本还不到它一个，应该先把便宜的做完，看清天花板在哪再动它。

---

## 建议执行顺序

| 批次 | 内容 | 预计 | 判据 |
|---|---|---|---|
| 1 | **F**（上色图指标 + 外部资产抽查纳入流程） | 半天 | 能复现 v3 的表，且新增两列指标 |
| 2 | **A + E**（跨名字竞争 + 每名字阈值） | 1～2 天 | 难负例误检 ≤ 0.15，mIoU ≥ 0.39，灰像素 ≤ 0.35 |
| 3 | **C**（近邻回退先上，组合式偏移随后） | 1 天 | 外部资产提示词命中 ≥ 50/51，留出集不退 |
| 4 | **B**（上下文 token，K = 4 起） | 1 天 | mIoU ≥ 0.41，且外部资产抽查不退 |
| 5 | **D**（在线难例） | 半天 | 第 2/3 epoch 不再空转 |
| 6 | **G / H** | 视情况 | 需要重新渲染 / 需要接受更重的产物 |

批次 2～5 全部做完，一个不算激进的预期是：阈值 0.5 上 **mIoU 0.368 → 0.42～0.45，灰像素 0.381 → 约 0.30，难负例误检 0.188 → 0.13～0.15**。这些是估计值，不是实测。

**每一批都必须在同一个留出集上比**：沿用 `concept_bank_v3/split.json`，或保证 2000 个物体集合不变（随机补的那 145 个由 `--seed` 和物体列表共同决定）。只报 mIoU 不报难负例误检的结果不作数——v3 的经验就是，光放宽检出很容易把 mIoU 做上去。
