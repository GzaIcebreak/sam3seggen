## 0. 一页结论

| 跑次 | 状态 | 判定 |
|---|---|---|
| `v5_paint` | 完成 | 只换画法：涂对涨、涂错也涨。argmax 本身不是免费午餐 |
| `v5_ce_bank` | 完成 | **未通过**。目标对了但没容量 |
| `v5_ce_lora` | 完成 | **定量过、定性不过**。留出集数字涨，外部资产肉眼是椒盐噪点，远不如 v3 |
| `v5_ce_lora_full` | 完成 | 加 `embed,proj` 后数字并列（差 0.002），噪点同样在，**容量不再是瓶颈** |

v4 的权衡线（推检出则涂错涨 / 压难负例则灰掉）在 **CE + LoRA + argmax** 这一格第一次被同时改善。在 v3 的工作点（未涂 0.200）上等覆盖比较：

| 方案 | 涂对 | 涂错 | 错涂占比 | 难负例 FP |
|---|---:|---:|---:|---:|
| v3 叠涂 @0.4 | 0.583 | 0.217 | 0.271 | 0.257 |
| **v5_ce_lora ep3，argmax τ=0.50** | **0.632** | **0.168** | **0.210** | **0.187** |
| v5_ce_lora_full ep3，argmax τ=0.51 | 0.634 | 0.166 | 0.208 | 0.183 |

三个数同向变好，不是换了个工作点。MakerWorld 涂对 0.581 → 0.724。叠涂列仍然塌，训练和部署必须走同一个 argmax。

**但外部资产（`3D拆件.zip`）肉眼否定了这组数字。** v5 的图是椒盐噪点：同一部件内部花成好几色，边缘碎，`sword` / `car` / `dog` 大面积灰。v3 叠涂是整块平涂。下游 SegviGen 抄的是颜色，这种碎斑会直接变成碎部件。定性比定量优先，**v5 不作为部署产物**，继续用 v3 的 `bank.pt` + 叠涂 @0.4。

未过硬的部分：hard 切片只有 14 张图；更重要的是数字和肉眼打架，下一轮必须把「块是否干净」写进过关条件，不能只看像素准确率。

## 0.1 技术路线

方案原文在 `PLAN_concept_bank_v5.md`。v4 的 A–H 都在同一条权衡线上滑：推检出则涂错涨，压难负例则灰掉。v5 的判断是三条同时错了——目标、容量、推理算子——必须换成**同一个**逐像素归属算子，缺一不可。下面四条是计划里的实验格，外加一条事后修补。

### 总路线：归属 CE + 点积两端容量 + argmax

**缺口。** (1) 训练是每名字独立 BCE+Dice（绝对分数），部署 `colorize` 是逐像素叠涂归属，BCE 从不问「这个像素是 arm 还是 body」。(2) v4 的 A 加了跨名字 CE，但竞争对象是 `logit(1−∏(1−m_q·s_q))`，梯度被两次 sigmoid 挤扁，参数又只有一次文本平移，推理仍走阈值叠涂——学到的排序部署用不上。(3) v4 的 H 证明 decoder LoRA 能把 loss 压到 v3 地板以下，但目标仍是 BCE，学到的是分数重校准，不是分辨。

**做法。** 三件事对齐成一个算子。名字级像素 logit `L_n(p) = logsumexp_q [M_{n,q}(p) + log s_{n,q}]`（原始 mask logit，不过 sigmoid），再加可学习背景标量 `b_bg`；损失是对正名 ∪ 负名 ∪ bg 的逐像素 softmax CE（类平衡 `1/√area`，近义词 `logsumexp` 合并不互罚，BCE+Dice 权重默认 0）。可训参数放在掩码点积两端：保留 v3 bank，LoRA r=8 挂 `mask,text`（查询怎么读文本 / 像素怎么被文本调制），不够再加 `embed,proj`。推理 `--assign argmax`：同一套 `L_n` 上 softmax 取胜者，`max prob < τ` 留灰。

**和 v4-A 的差别。** A：`CE(logit(union_prob), ids)`，参数只有文本偏移，推理仍是阈值叠涂。v5：`CE(logsumexp(mask_logit + log s), ids)`，参数在点积两端，推理用同一个 softmax 的 argmax。

**实测 / 判定。** 见下面四格。定量上权衡线第一次被同时改善；定性上 argmax 把「认错」变成「认碎」，**不部署**。

### `v5_paint`：零训练，只换画法

**缺口。** v3 的点积里也许已经有相对排序，只是被「小掩码优先叠涂」丢掉了。先量这个，再决定值不值得训。

**做法。** v3 `bank.pt`，`--eval_only`，同一套前向分别用叠涂和 `paint_argmax` 上色。

**实测。** 叠涂复现 v3（涂对 0.541 / 涂错 0.205）。argmax τ=0 涂对到 0.650，涂错也到 0.305；τ=0.5 仍是 0.618 / 0.258。难负例 FP 在 argmax 定义下从 0.19 跳到 0.8（负名赢了任何前景像素就算）。

**判定。** 排序信息 v3 里有一部分，但换画法本身过不了「涂错 ≤ 0.16」。argmax 不是免费午餐，后面必须带着 CE 一起训。

### `v5_ce_bank`：CE，只训 bank

**缺口。** 目标对了、容量还是 v3 那次平移，会不会像 A 一样学不动？

**做法。** `--assign_ce 1 --epochs 3 --resume v3`，无 LoRA。~58 min。

**实测。** 等覆盖落在 τ=0.3 和 0.5 之间，涂错估 ~0.18，过不了 0.16。叠涂列走回「更敢涂」（涂对 0.505 / 涂错 0.321）。

**判定。** 未通过。和方案预期一致：没有点积两端的容量，CE 改不了像素级排序。

### `v5_ce_lora`：CE + LoRA `mask,text`（主实验）

**缺口。** H 的容量（28 层 / 114688 参数）配上对的目标，训练和部署走同一个 argmax，三条是否一起动。

**做法。** `--assign_ce 1 --decoder_lora 8 --lora_scope mask,text --lr_lora 1e-4 --resume v3`。~61 min。叠涂列只作对照（预期会塌，因为 LoRA 在绝对分数上重校准）。

**实测。** 叠涂 @0.5 全程塌（ep2 涂对 0.343）。argmax 在未涂 0.200 的等覆盖点：涂对 0.632 / 涂错 0.168 / 难负例 0.187，对 v3 叠涂 @0.4 的 0.583 / 0.217 / 0.257，三个数同向变好。MakerWorld 涂对 0.581 → 0.724。τ 是干净的覆盖/纯度旋钮，错涂占比单调下降。

**判定。** 定量过、定性不过。外部资产（`3D拆件.zip`）是椒盐噪点：同一部件内部花成好几色，下游 SegviGen 会抄成碎部件。**不作为部署产物。**

### `v5_ce_lora_full`：再加 `embed,proj`

**缺口。** `mask,text` 只改查询怎么读文本、像素怎么被调制；点积左右两端（`mask_embedder` / `instance_projection`）还没动。容量是不是还不够。

**做法。** `--lora_scope mask,text,embed,proj`，其余同主实验。

**实测。** 等覆盖点涂对 0.634 / 涂错 0.166，与主实验差 0.002；噪点同样在。

**判定。** 容量不再是瓶颈。再加靶点没有收益，也不治碎斑。

### 事后修补：query 门控 + 连通块清理

**缺口。** argmax 每个像素独立做决定，没有空间平滑。门控弱 query、清小碎块，能不能在不改训练的情况下把块黏回去。

**做法。** `query_gate(gate_rel / gate_topk)` 在 `logsumexp` 前丢掉低分 query；`clean_components(min_comp)` 把小于剪影份额的连通块改标到邻域。接进 `concept_bank` 与 `sam3_to_2dmap`。

**实测。** 留出集等覆盖上数字仍胜 v3，只清碎块几乎不动（0.635 / 0.165）。门控在外部资产上暴露另一层：sword 的 `guard` query 在 LoRA 后覆盖整把剑，门控去掉噪声后 blade 0 像素——**不是噪点，是 LoRA 把掩码形状改坏了**。oracle（§7）进一步说明：v3 冻结解码器的 200 个候选里已经有正确掩码（像素上限 0.92），错在分数把正确的排到第 38 位；v5 把「选掩码」换成「选像素」，碎片化是算子定义。

**判定。** 修补救不了。下一轮改走候选级选择 + 掩码级叠涂，见 `REPORT_mask_rank_v3.md`。

## 4. τ 扫描与等覆盖对比

`queue_v5_tau.sh`：对 `ce_lora` / `ce_lora_full` 的 ep2、ep3 用 `--eval_only --assign_taus 0.5,0.6,0.7,0.8,0.9` 重评。
原因是主实验只扫到 τ=0.5，而那时未涂已经低于 v3 的 0.20~0.25，**没有等覆盖点可比**。

`v5_ce_lora` ep3 的完整曲线（holdout 240 图 / 1068 prompt）：

| τ | 未涂 | 涂对 | 涂错 | 错涂占比 | 难负例 FP | 涂到部件 |
|---:|---:|---:|---:|---:|---:|---:|
| 0.5 | 0.198 | 0.633 | 0.169 | 0.211 | 0.188 | 0.539 |
| 0.6 | 0.330 | 0.553 | 0.117 | 0.175 | 0.124 | 0.462 |
| 0.7 | 0.467 | 0.456 | 0.077 | 0.144 | 0.094 | 0.393 |
| 0.8 | 0.615 | 0.349 | 0.036 | 0.095 | 0.064 | 0.314 |
| 0.9 | 0.776 | 0.214 | 0.010 | 0.045 | 0.022 | 0.208 |

τ 是干净的覆盖/纯度旋钮，且**错涂占比单调下降**——不是简单地把像素挪进灰区，而是先放弃最没把握的像素。
四个候选（`ce_lora`/`ce_lora_full` × ep2/ep3）在任一等覆盖点上差距都在 0.002 以内，见 §0 的表。

涂对 0.632/0.602、涂错 0.168/0.148，都优于 v3 的 0.583/0.217 与 0.541/0.205。

## 6. 外部资产实测（`3D拆件.zip` 10 个模型）

`assets/ext_bench/compare_{front,back}.png` = git 原版 10 列（`2f4e83b`）右边接上 v5 三档 τ，不是整张替换。
这批资产没有部件 GT，命中率/覆盖率只能当附注，**过关看肉眼**。

| 变体 | 提示词命中率 | 前景覆盖率 | 肉眼 |
|---|---:|---:|---|
| v3 叠涂 @0.4 | 0.90 | 0.88 | 整块平涂，可用 |
| v5 argmax τ=0.5 | 0.91 | 0.80 | 椒盐噪点，不可用 |
| v5 argmax τ=0.6 | 0.84 | 0.67 | 更灰，噪点还在 |
| v5 argmax τ=0.7 | 0.82 | 0.53 | 大面积灰掉 |

数字说 τ=0.5 和 v3 平手，图说不是一回事。v5 每个像素独立 argmax，没有空间平滑，所以：

- 同一部件内部花成好几色（`dog` 脸、`car` 车身、`pineapple` 叶子、`mickey` 后背）
- 调高 τ 只是把没把握的像素涂灰，碎斑不会黏成块（`sword` 剑身 τ=0.5 就灰了一半，τ=0.7 整把灰）
- 部件多的资产（`robot` / `human` / `chair`）覆盖率看起来涨了，但块也不干净

结论：**argmax 逐像素竞争把「认错」变成了「认碎」。** 定量指标按像素计数，看不见这个。下游要的是整块颜色，v5 这轮不合格。下一轮如果还走归属损失，必须带空间约束（CRF / 亲和扩散 / 先出实例再上色），不能再拿像素准确率当过关线。

## 7. 碎片化的根因与去噪修补的上限

去噪修补（`sam3_bank.query_gate` / `clean_components`，接进 `concept_bank --gate_rel/--gate_topk/--min_comp` 与
`sam3_to_2dmap`，队列 `queue_v5_gate.sh`）在留出集等覆盖点（未涂 0.200）上：

| 画法 | 涂对 | 涂错 | 硬FP |
|---|---:|---:|---:|
| v3 叠涂 @0.4 | 0.583 | 0.217 | 0.257 |
| v5 原样 | 0.632 | 0.168 | 0.187 |
| v5 + 只清碎块 | 0.635 | 0.165 | 0.183 |
| v5 + rel0.5 门控 + 清碎块 | 0.613 | 0.187 | 0.225 |
| v5 + rel0.7 门控 + 清碎块 | 0.605 | 0.195 | 0.228 |

数字仍胜 v3，但外部资产上门控暴露出另一层问题：sword 的 `guard` query 在 LoRA 后的解码器里覆盖整把剑，
门控去掉噪声 query 后 blade 0 像素、guard 3289 像素——**不是噪点，是 LoRA 把掩码形状改坏了**。修补救不了这个。

`runs/oracle_v3` / `runs/oracle_v5`（`oracle_candidates.py`，同一留出集）把根因量化了：

| | v3 冻结 SAM3 | v5 LoRA 解码器 |
|---|---:|---:|
| SAM3 自己的 top-1 候选 IoU | 0.404 | 0.428 |
| 200 个候选里最好的那个 IoU | 0.700 | 0.702 |
| 最好候选恰好是 top-1 的比例 | 11% | 3.7% |
| 最好候选的分数排名中位数 | 38 | 63 |
| 只保留 precision ≥ 0.7 候选后叠涂 | 涂对 0.797 / 涂错 0.017 | – |
| 像素上限（正确候选覆盖即算对） | 0.924 | 0.875 |

冻结解码器的 200 个候选里**已经有**正确且完整的掩码（上限 0.92），问题只在**选哪一个**：SAM3 自己打的分把正确掩码排在第 38 位。
v5 的做法是让所有候选逐像素混战再用 LoRA 改 logit，等于把「选掩码」换成「选像素」——碎片化是这个算子的定义，不是 bug；
LoRA 还让排序更差（中位数 38 → 63）。
